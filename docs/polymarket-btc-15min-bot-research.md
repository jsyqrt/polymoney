## 1. Polymarket 市场概述

### 1.1 平台基础

Polymarket 是基于 **Polygon 区块链** 的去中心化预测市场平台。

| 特性 | 说明 |
|------|------|
| 底层链 | Polygon (Layer 2) |
| 结算货币 | USDC |
| 订单簿类型 | CLOB (Central Limit Order Book) |
| 交易费用 | 极低（约0.1%手续费） |

### 1.2 市场机制

- 每个市场有两个结果代币：**YES** 和 **NO**（或 **Up** 和 **Down**）
- 价格范围：$0.00 - $1.00
- 事件结束后结算：正确结果代币价值 $1.00，错误结果价值 $0.00
- **YES + NO 价格始终 = $1.00**（由共享订单簿机制保证）

## 2. 共享订单簿机制

> ⭐ 这是 Polymarket 最核心的技术特性，理解它对于设计交易策略至关重要。

### 2.1 核心原理

**YES 和 NO 不是两个独立的代币，而是"一美元被撕成两半"**

```
想象每张兑换券价值永远 = 1 美元
市场把它撕成两半：一半写 YES，一半写 NO

结算时：
├── 事件发生：   YES = $1.00, NO = $0.00  → 1 + 0 = 1
└── 事件不发生： YES = $0.00, NO = $1.00  → 0 + 1 = 1
```

### 2.2 订单自动镜像

当你在 YES 市场挂单时，系统会自动在 NO 市场创建对应订单：

| 你的操作 | 系统自动创建 |
|----------|-------------|
| YES 买单 @ $0.18 | NO 卖单 @ $0.82 |
| YES 卖单 @ $0.75 | NO 买单 @ $0.25 |

### 2.3 自动撮合机制

```
交易者 A: 挂 YES 买单 @ $0.60
交易者 B: 挂 NO 买单 @ $0.40

因为 0.60 + 0.40 = 1.00
系统立即撮合！其他人看不到这两个订单

留在订单簿上的只有 YES + NO > 1 的订单
```

### 2.4 关键结论

| 误解 | 真相 |
|------|------|
| 同一市场 YES + NO < 1 可以套利 | ❌ 不可能，系统会自动撮合 |
| YES 和 NO 是独立定价的 | ❌ 共享订单簿，价格互相约束 |
| 可以在同一市场低买高卖 | ❌ 只有 spread > 0 的挂单才会存在 |

## 3. 仓位套利策略原理

### 3.1 核心思想

仓位套利是一种**做市商套利策略**，其核心思想是：

> **只要 Up + Down 的总买入成本 < $1，就一定能盈利**

因为无论最终结果如何：
- Up 胜 → Up 代币结算为 $1/份
- Down 胜 → Down 代币结算为 $1/份

只要持有两边，总能获得 $1/份的结算价值。

### 3.2 数学原理

设：
- `U` = Up 持仓份数
- `D` = Down 持仓份数
- `C` = 总成本（Up成本 + Down成本）
- `min(U,D)` = 对冲仓位（较小方）

**结算价值计算：**
```
如果 Up 胜：结算价值 = U × $1
如果 Down 胜：结算价值 = D × $1
```

**盈亏计算：**
```
Up 胜时 PnL = U - C
Down 胜时 PnL = D - C
最坏情况 PnL = min(U, D) - C
```

**盈利条件：**
```
稳赚不赔 ⟺ 最坏情况 PnL ≥ 0
         ⟺ min(U, D) ≥ C
         ⟺ C / min(U, D) < 1
         ⟺ 有效成本率 < 100%
```

### 3.3 限价单策略

由于共享订单簿机制，**直接以市价买入两边的成本必然 = 100%**。

因此策略使用**限价单**以低于市价买入：

```
目标成本率设定：target_cost = 98%（例如）

市场价：Up = 60%, Down = 40%（和 = 100%）
限价计算：按比例缩放使限价和 = 98%
  Up 限价 = 60% × 0.98 = 58.8%
  Down 限价 = 40% × 0.98 = 39.2%

限价和 = 98% < 100%，存在套利空间
```

### 3.4 成交机制

限价单的成交条件：
```
市场价 ≤ 限价 → 成交
成交价 = 市场价（以更优价格成交）
```

这意味着：
1. 订单挂出后等待市场波动
2. 当市场价格下跌到限价以下时成交
3. 实际成交价可能优于限价

### 3.5 仓位平衡问题

由于两边成交时机不同，会出现**仓位不平衡**：

```
理想状态：Up 50份, Down 50份（完美对冲）
实际状态：Up 60份, Down 30份（Up 超配）

风险分析：
- Down 胜时：只有 30 份结算，可能亏损
- 需要通过策略调整来恢复平衡
```

## 4. 策略核心指标

### 4.1 有效成本率（Effective Cost Rate）

**定义：** 有效成本率 = 总成本 / 较小方份额

```
有效成本率 = C / min(U, D)
```

**意义：**
- 这是最核心的盈亏判断指标
- **有效成本率 < 100% ⟺ 稳赚不赔**
- 有效成本率越低，利润空间越大

**证明：**
```
有效成本率 < 1
⟺ C / min(U,D) < 1
⟺ C < min(U,D)
⟺ 最坏PnL = min(U,D) - C > 0
```

### 4.2 仓位平衡度（Balance Ratio）

**定义：** 仓位平衡度 = 较小方份额 / 较大方份额

```
平衡度 = min(U, D) / max(U, D)
```

**意义：**
- 范围 0~1，越接近 1 越平衡
- 1.0 = 完美平衡
- 0.0 = 完全单边（高风险）

### 4.3 对冲成本率（Hedged Cost Rate）

**定义：** 对冲成本率 = Up均价 + Down均价

```
对冲成本率 = avg_price(Up) + avg_price(Down)
```

**注意：** 这个指标不考虑仓位不平衡，仅反映单位对冲仓位的成本。

### 4.4 最坏情况盈亏（Worst Case PnL）

**定义：** 最坏情况盈亏 = min(Up胜盈亏, Down胜盈亏)

```
最坏PnL = min(U - C, D - C)
```

**意义：**
- 只有 最坏PnL ≥ 0 才能保证稳赚不赔
- 是风险控制的底线指标

### 4.5 仓位状态（Position Status）

| 状态 | 条件 | 说明 |
|------|------|------|
| `perfect` | 最坏PnL ≥ 0 | 无论结果如何都盈利 |
| `profitable` | 期望利润 ≥ 0，但最坏PnL < 0 | 期望盈利但有风险 |
| `risky` | 期望利润 < 0 | 期望亏损 |
| `empty` | 无仓位 | - |

## 5. 分阶段执行机制

### 5.1 阶段划分

针对短周期市场（如15分钟），策略采用分阶段执行：

| 阶段 | 时间 | 目标 | 策略 |
|------|------|------|------|
| **建仓期** | 0-5分钟 | 建立基础仓位 | 双边下单，快速建仓 |
| **优化期** | 5-10分钟 | 优化成本结构 | 双边下单，关注成本 |
| **补板期** | 10-15分钟 | 补齐短板 | 专注落后方，不买低概率方 |

### 5.2 建仓期策略

目标：快速建立双边仓位

- 双边同时下单
- 关注仓位平衡，落后方优先
- 允许略微牺牲成本以换取建仓速度

### 5.3 优化期策略

目标：在保持平衡的同时优化成本

- 双边下单，但更关注成本率
- 严格控制有效成本率不恶化
- 根据市场价格动态调整限价

### 5.4 补板期策略

目标：最后阶段专注修复仓位不平衡

关键规则：
1. **不买低概率方**：当一边价格 < 5% 时，不再买入该方
2. **专注落后方**：只给仓位较少的一方下单
3. **接受更高成本**：可以以接近市价的价格买入，优先恢复平衡

**原因：** 在接近结算时，低概率方可能归零，此时买入风险极高。

### 5.5 仓位失衡处理

当仓位严重失衡（差异 > 10%）时：

```
失衡检测：
gap_ratio = |U - D| / max(U, D)
if gap_ratio > 10%:
    暂停领先方下单
    加大落后方下单金额
```

极端失衡（单边仓位）时：
- 允许落后方限价 = 市场价
- 目标是尽快恢复平衡，即使暂时有效成本率略高

### 5.6 限价计算逻辑

**基本计算：**
```
如果市场价和 > 目标成本：
    scale = 目标成本 / 市场价和
    Up限价 = Up市价 × scale
    Down限价 = Down市价 × scale
否则：
    直接使用市场价（本身就有套利空间）
```

**失衡调整：**
```
如果仓位失衡：
    向落后方倾斜价格（提高限价使其更容易成交）
    同时降低领先方价格（保持限价和不变）
```

## 6. 风险管理与合规

### 6.1 主要风险

| 风险类型 | 描述 | 缓解措施 |
|----------|------|----------|
| **仓位不平衡风险** | 单边仓位过多 | 分阶段策略，落后方优先 |
| **成本超标风险** | 有效成本率 > 100% | 下单前检查预测成本率 |
| **流动性风险** | 订单无法成交 | 动态调整限价，设置超时取消 |
| **结算风险** | 争议导致延迟结算 | 选择高流动性市场 |

### 6.2 下单前检查

每次下单前必须验证：

1. **基础检查：** 限价 > 0，订单金额 > 0
2. **价格检查：** 限价 ≤ 市场价（否则无法成交）
3. **成本率检查：** 预测下单后的有效成本率不能大幅恶化
4. **阶段检查：** 第三阶段不买低概率方

### 6.3 订单管理

**超时取消：** 订单超过设定时间（如60秒）未成交则取消

**价格偏离取消：** 市场价远离限价（如高10%以上）时取消

**成交记录：** 记录所有成交，更新仓位和成本
